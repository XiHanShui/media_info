# 字节访问与大文件策略

Type: grilling
Blocked by: 01

## Question

解析器**怎么读字节**，以及**面对大文件怎么办**？

要定下来的：

- **字节访问层**：随机访问文件句柄（`RandomAccessFile`）、内存映射、还是分段流式读取？各自的取舍——大文件能否只读需要的区间（这决定能不能秒开一个 4GB 的视频）？
- **64 位长度**：MP4 的 `largesize`（32 位长度占位 + 64 位实际长度）和 `co64`（64 位 chunk offset）怎么支持？文件偏移量用 Dart 的 `int`（64 位）是否够？
- **`mdat` 在文件尾部的常见布局**：媒体数据通常在 moov 之前或之后，两种布局都要能只读 moov 就出结果。
- **建树策略**：一次读完整个结构树，还是**惰性展开**（点开某个块时才读它的子块）？moov 里上万个 `stts`/`stsc`/`stsz` 条目时，全量建树的代价是多少？
- **有损/截断文件**：读到文件尾但声明长度还剩一大截，怎么表现——报"截断"还是尽量解析已读到的部分？

**产出**：字节访问层方案 + 大文件与截断文件的行为约定（写清楚"遇到 X 时，界面显示什么"）。

**为什么阻塞于票 01**：节点模型决定了树里要不要带偏移量、以及能不能惰性展开——这两点直接决定本票的答案。
