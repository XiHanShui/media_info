# MP3：帧解析 + 叶子提取器

Status: ready-for-agent
Blocked by: 13

## Question / 任务

实现 **MP3** 的帧序列解析与语义字段提取。

**必读**：`docs/design/core-api.md`、[字节访问与大文件策略](06-byte-access-large-files.md)（大文件 + 惰性展开）。

**注意**：MP3 **没有真正的块树**——它是连续的帧序列。结构树里按**帧列表**呈现（每帧一个节点，type 用 `MPEG Audio Frame`），但每个帧节点上挂它的帧头字段。

**解析**（`lib/src/formats/mp3.dart`）：

- 文件开头可能有 `ID3v2` 标签（长度是 syncsafe 整数字节）→ 跳过，但记下它的偏移与大小。
- 帧头 4 字节：11 bit sync、2 bit version、2 bit layer、1 bit protection、4 bit bitrate index、2 bit samplerate index、1 bit padding、1 bit private、2 bit channel mode、2 bit mode extension、1 bit copyright、1 bit original、2 bit emphasis。
- 帧长 = `floor(samples_per_frame / samplerate * bitrate / 8) + padding`。
- 用 sync 连续性校验帧边界；坏帧不终止解析，标记并继续。

**叶子提取器**：`codec`（`MPEG-1 Layer 3` 之类，由 version+layer 组合）、`sample_rate`、`channels`（channel mode）、`duration`（总帧数 × 每帧采样数 ÷ 采样率）、`bit_depth`（不适用 → 不产出）、`overall_bitrate`（derived）。格式特有字段 `mpeg_version` / `layer` / `bitrate_mode`（CBR/VBR）挂在帧节点上。

**测试**（`test/formats/mp3_test.dart`）：用 `test/fixtures/mp3_cbr128_44100_stereo.normal.mp3`、`mp3_vbr_q2_22050_mono.edge.mp3`、`mp3_cbr128_44100_stereo.normal.truncated.mp3`。

**格式嗅探（本票必须实现）**：本格式要实现自己的 `detect` 回调并随 `FormatSpec` 一起注册。嗅探**只看文件头**，不参与扩展名判定：

- WAV：偏移 0 是 `RIFF`，偏移 8 是 `WAVE`
- AIFF：偏移 0 是 `FORM`，偏移 8 是 `AIFF`
- FLAC：偏移 0 是 `fLaC`
- MP4 / MOV：偏移 4 是 `ftyp`
- Matroska / WebM：偏移 0 是 `1A 45 DF A3`
- MP3：偏移 0 是 `ID3`，或帧同步 `0xFF Ex/Fx`

注册方式：`registerFormat(FormatSpec(name: ..., container: ..., extractor: ..., detect: ...))`，**从你自己的文件里调用，不要改 `lib/src/core/registry.dart`**（并行合并冲突的高发点）。注册顺序即嗅探顺序。

**扩展名不符也要能正确识别**：测试里把本格式的样本复制成**错误的扩展名**（例如 `mislabelled.wav`）到临时目录，断言 `detectFormat` 仍返回本格式。

**约束**：纯 Dart，无新依赖。`flutter analyze` 无 issue。
